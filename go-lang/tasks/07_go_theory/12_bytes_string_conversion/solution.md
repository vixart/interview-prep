# Решение

## Разбор

1. Объяснить, почему обычная конвертация `string(b)` и `[]byte(s)` копирует данные:
   строка неизменяема, а слайс — изменяем, поэтому компилятор обязан скопировать,
   иначе изменение слайса «сломало» бы строку.
2. Рассказать, когда компилятор умеет избегать аллокации сам
   (например, `string(b)` как ключ map: `m[string(b)]`, сравнение, `switch`,
   конкатенация в `Write*`).
3. Показать «unsafe» способ конвертации без копирования и объяснить его опасность:

```go
// Go 1.20+
func bytesToString(b []byte) string {
    return unsafe.String(unsafe.SliceData(b), len(b))
}

func stringToBytes(s string) []byte {
    return unsafe.Slice(unsafe.StringData(s), len(s))
}
```

   Важно: полученную строку нельзя использовать после изменения исходного слайса;
   а байты, полученные из строки, изменять нельзя вообще (строка может лежать
   в read-only памяти → segfault).
4. Обозначить, когда это оправдано: горячий путь, парсеры, большие объёмы данных,
   и только после профилирования.
