# Решение

## Разбор

1. Реализовать кэш с корректной работой в конкурентной среде.
2. Разобрать варианты:
   - `map` + `sync.RWMutex` — универсальный вариант;
   - `sync.Map` — оптимизирована под сценарии «много читателей, ключи пишутся один раз»
     (метод `LoadOrStore`), но проигрывает при частых записях и не типизирована;
   - `golang.org/x/sync/singleflight` — чтобы дорогое вычисление для одного ключа
     выполнялось ровно один раз, даже если его одновременно запросили N горутин.
3. Объяснить, когда `sync.Map` действительно нужна, а когда обычная мапа под мьютексом
   быстрее и понятнее.
