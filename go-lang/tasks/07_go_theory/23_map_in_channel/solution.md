# Решение

## Разбор

1. Предсказать вывод: во все 5 элементов `stockHistory` попадает **одна и та же**
   мапа (мапа — ссылочный тип), поэтому история будет содержать 5 одинаковых
   финальных состояний, а не снимки на каждой итерации.
2. Найти проблемы:
   - передача одной и той же мапы в канал → шаринг мутируемого состояния между
     горутиной-писателем и main → гонка данных (`go run -race`);
   - канал никогда не закрывается — горутина остаётся висеть, если читатель уйдёт раньше;
   - изменение мапы во время `range` по ней (здесь безопасно, т.к. ключи не добавляются,
     но об этом стоит сказать).
3. Исправить: отправлять в канал **копию** мапы на каждой итерации,
   закрывать канал по завершении и читать через `for range`.
