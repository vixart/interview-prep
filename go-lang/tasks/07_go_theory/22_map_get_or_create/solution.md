# Решение

## Разбор и подсказки

- Обычная `map` не безопасна для конкурентного доступа: чтение+запись из разных
  горутин даёт `fatal error: concurrent map read and map write`.
- Наивный вариант «`RLock` → проверили → `RUnlock` → `Lock` → записали» содержит гонку:
  между разблокировкой и блокировкой другой горутина успеет вставить своё значение.
  Нужна повторная проверка под `Lock` (double-checked locking) — тогда обе горутины
  гарантированно получат **одно и то же** значение (то, которое записали первым).
- Обсуждается, почему здесь не подходит просто `sync.Map` и когда она уместна.
