# Решение

## Проблемы

1. **SQL-инъекция**: запрос собирается через `fmt.Sprintf` — нужны параметризованные
   запросы (`db.Exec("insert ... values ($1,$2,$3,$4)", ...)`).
2. **Соединение с БД открывается на каждый вызов** `updateCurrency` и тут же закрывается.
   `sql.DB` — это пул, его надо создавать один раз при старте и переиспользовать
   (`SetMaxOpenConns`, `SetMaxIdleConns`, `SetConnMaxLifetime`).
3. **`panic` вместо возврата ошибки** в библиотечной функции; ошибки нужно
   оборачивать (`fmt.Errorf("...: %w", err)`) и обрабатывать наверху.
4. **Нет `context`**: ни у HTTP-запросов, ни у запросов в БД —
   `http.NewRequestWithContext`, `db.ExecContext`.
5. **У `http.Client` не задан `Timeout`** → запрос может висеть вечно.
   Плюс не закрывается `resp.Body`, не проверяется `StatusCode`.
6. **Секреты (пароль БД) в константах в коде** — должны читаться из окружения/конфига.
7. **Последовательный обход банков** — можно распараллелить (errgroup + семафор).
8. **Отладочный `fmt.Println("Connected!")`**, отсутствие логгера и метрик.
9. **Вся логика в `main`**, разбор аргументов вручную (лучше `flag`/`cobra`),
   нет разбиения на слои и нет тестов.
