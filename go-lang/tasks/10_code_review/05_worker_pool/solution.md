# Решение

## Проблемы

1. **«Пул» не является пулом**: воркеров создаётся ровно столько же, сколько задач
   (`for range tasks`) — смысл ограничения теряется. Число воркеров должно быть
   параметром (например, `runtime.NumCPU()`).
2. **`jobChan` никогда не закрывается** → воркеры навсегда висят на `range jobs`
   после обработки всех задач — утечка горутин.
3. **Нет `sync.WaitGroup`** и нет закрытия `resultChan`; сбор результатов
   держится на том, что их ровно `len(tasks)` — хрупко и ломается при паниках/ошибках.
4. **Паника в воркере** уронит всю программу — нужен `defer recover()`
   на уровне воркера или явная обработка.
5. **Нет `context`** — нет способа отменить обработку.
6. `math/rand` без сидирования (в старых версиях Go) и общий генератор
   как точка конкуренции.
7. Ошибки только печатаются, не агрегируются; результат обработки нигде не собирается.

## Правильный каркас

```go
jobs := make(chan Task)
results := make(chan Result, len(tasks))

var wg sync.WaitGroup
wg.Add(workers)

for i := 0; i < workers; i++ {
    go func() {
        defer wg.Done()
        worker(ctx, jobs, results)
    }()
}

go func() {
    defer close(jobs)
    for _, t := range tasks {
        jobs <- t
    }
}()

go func() {
    wg.Wait()
    close(results)
}()

for res := range results { /* ... */ }
```

Полный исправленный вариант: [`fixed.go`](fixed.go) (запускается: `go run fixed.go`).
