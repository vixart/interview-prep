# Решение

## Проблемы

1. **SQL-инъекция**: `period` берётся из query-параметра и подставляется в запрос
   строкой → параметризованный запрос + валидация допустимых значений (`week`/`day`).
2. **Игнорирование ошибок**: `sql.Open`, `getVisitsFromDB`, `json.Marshal`,
   `w.Write`, `http.ListenAndServe` — все `_`. Нужны проверки и корректные
   HTTP-коды (400/500) в ответе.
3. **Потеря контекста запроса**: используется `context.Background()` вместо `r.Context()`,
   поэтому отмена клиентом не доходит до БД.
4. **Ключ контекста — строка**: нужен приватный тип ключа
   (`type ctxKey struct{}`), иначе возможны коллизии; а вообще передавать `period`
   параметром функции, а не через контекст.
5. **Порядок аргументов**: `ctx` должен быть первым параметром (`func getVisitsFromDB(ctx, db)`).
6. **Секреты в коде**: строка подключения с паролем захардкожена.
7. **Нет настроек пула** (`SetMaxOpenConns`, `SetConnMaxLifetime`), нет `db.PingContext`.
8. **Нет таймаутов у HTTP-сервера** (`ReadHeaderTimeout`, `WriteTimeout`)
   и graceful shutdown.
9. **Не выставляется `Content-Type: application/json`**.
10. **Типы данных**: день как `string` вместо `time.Time`, отсутствие тегов `json`
    у полей `DayVisit` (в JSON поля пойдут с заглавной буквы).
11. **Группировка/подсчёт топ-локации в Go**, хотя это эффективнее сделать
    на стороне БД одним запросом.
