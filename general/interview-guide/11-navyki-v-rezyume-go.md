# Навыки в резюме Go-разработчика: что писать, исходя из спроса

Какие навыки указывать в резюме — не «что я знаю», а «что чаще всего требуют
в вакансиях». Основа — анализ всех Go-вакансий на hh.ru по частотности навыков
в тегах.

Почему упоминаний меньше, чем вакансий (по запросу «golang» вакансий ~700):
далеко не все работодатели заполняют графу навыков/тегов, либо пишут иначе
(«Go» вместо «Golang») — статистика от этого проседает.

## Ключевые выводы

- **Навыки — это семантическое ядро резюме.** Фильтры и HR оценивают «в тупую»,
  по совпадению ключевых слов — как теги/хештеги. Не надеяться на здравый смысл
  читателя («ну очевидно же, что я знаю Git») — не совпал по ключевикам → отбраковали.
- **Писать самый частотный вариант названия:**
  - «Golang» упоминается почти в 4 раза чаще, чем «Go» — указывать оба;
  - «Kubernetes» — 8-е место, а модное «k8s» — около сотого. Писать полностью;
  - Git (85) и SQL (76) указывать обязательно, даже если кажется «моветоном» —
    «я же написал PostgreSQL, очевидно, что SQL знаю» не работает.
- **База Go-стека, которая «никуда не уходит»:** Golang, PostgreSQL, Docker,
  Redis, Kubernetes, Linux.
- **СУБД:** если опыт был с MySQL/Oracle — смело ставить и PostgreSQL: для
  типового CRUD-разработчика разница невелика, догнать легко. При прочих равных
  выгоднее указывать Postgres (158 против 50 у MySQL).
- **Кеши:** работал с memcached — пиши Redis (то же семейство, Redis сильно
  популярнее, memcached почти не упоминают).
- **Очереди:** RabbitMQ и Kafka идут почти вровень; если выбирать — Kafka
  предпочтительнее. Лучше пощупать обе: на сайте RabbitMQ в Get Started есть
  7 туториалов, и в каждом есть вариант на Go — прошёл уроки, вот уже и
  «работал с RabbitMQ». С Kafka — та же история.
- **Второй язык расширяет воронку:** Python (70), PHP (48), Java (32) в
  Go-вакансиях — это легаси, которое переписывают на Go, и интеграции
  (например, Python в ML-обвязке). Если есть такой бэкграунд — указывать.
- **gRPC (38) популярнее REST API (32)** в тегах Go-вакансий — тренд последних лет.

## Как применять

1. Взять этот топ как основу — в резюме стоит иметь порядка 30 навыков.
2. Не копировать всё подряд (одновременно питонист-пхпшник-джавист выглядит глупо) —
   **адаптировать под конкретную вакансию**: открыть целевые вакансии, посмотреть
   их теги (например: Kubernetes, ClickHouse, RabbitMQ, Kafka, gRPC) и добавить
   пересекающиеся ключевики к себе.
3. Выкинуть редкие/устаревшие навыки, по которым нет мэтча с вакансиями
   («настраивал NTP-протокол 10 лет назад»), и не писать нестандартные варианты
   названий — всё это срезает статистику мэтчинга.
4. Относиться к выходу на рынок как к бизнесу: сначала анализ рынка, потом продукт.
   Резюме — коммерческое предложение; чтобы дорого себя продать, нужно понять,
   «что нынче в ходу и что покупают», и адаптироваться под спрос.
