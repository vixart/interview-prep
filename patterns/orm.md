# Паттерны работы с БД: Active Record, Data Mapper, Unit of Work

Три паттерна из «Patterns of Enterprise Application Architecture» (Fowler),
о которых спрашивают в контексте любого ORM.

## Active Record vs Data Mapper

| | Active Record | Data Mapper |
|---|---|---|
| Идея | Модель **сама** знает, как себя загрузить и сохранить | Сущности **не знают** о базе; сохранение — во внешнем слое |
| Объект — это | Данные + поведение + доступ к БД (`user.Save()`) | Только данные + доменная логика |
| Работа с БД | Внутри модели | В mapper / repository |
| Плюсы | Быстро писать, мало кода, очевидно | Домен чист от инфраструктуры, легко тестировать без БД |
| Минусы | Домен сцеплен с БД, тесты тянут базу, сложные инварианты размазываются | Больше кода и слоёв |
| Примеры | GORM (Go), ActiveRecord (Rails) | Hibernate/JPA (Java), sqlc/чистые репозитории (Go) |

Правило выбора: CRUD-приложение с простой логикой — Active Record не
мешает; богатая доменная модель и инварианты — Data Mapper + repository.

## Unit of Work

Механизм, который позволяет работать с объектами в памяти, а синхронизацию
с БД берёт на себя: копит изменения (new/dirty/removed), а затем одним
`flush`/commit записывает всё **одной согласованной транзакцией** в
правильном порядке.

```
работаешь с объектами → UoW отслеживает изменения → один flush = один commit
```

Что даёт: меньше ручных `UPDATE`, автоматический порядок вставок по связям,
атомарность бизнес-операции целиком.

### Когда Unit of Work мешает

- **Bulk update / delete** — миллионы строк по одной сущности через UoW
  означают миллионы объектов в памяти и лавину отдельных запросов.
- Массовые импорты, отчёты, миграции данных.

В этих случаях ORM обходят: пишут запрос напрямую через соединение
(`UPDATE ... WHERE ...` одним стейтментом) или батчами, периодически
очищая контекст отслеживания.

## Для собеседования

- Ключевой вопрос различия: «знает ли доменный объект о своей персистенции?»
- Unit of Work — причина, почему «ORM тормозит на батчах»: он не для
  массовых операций, это не баг, а граница применимости.
- Repository поверх Data Mapper — стандартная связка: домен видит только
  интерфейс `UserRepository`, реализация с SQL живёт в инфраструктуре
  (это же DIP из [SOLID](solid.md)).
